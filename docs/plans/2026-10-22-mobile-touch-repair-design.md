# Phone scrolling and focus repair (slice M0): build contract (2026-10-22)

This is the contract the M0 implementers built against. The findings, the research and the test results are in `docs/audits/2026-10-22-mobile-usability-review.md`; the run plan is `docs/handoffs/2026-10-22-herdr-adoption-operator.md`. Review fixes after the first build changed three points, noted at the end.

Key measured facts (details in the review note):
- Browser xterm sits on the NORMAL buffer (phone walk F16; H1 escalation): tmux's `?1049h` is emitted before the WS exists and is dropped. Local xterm scrollback is unreliable (1 line on a live session; a 10,000-line replay copy after reload, with duplicates). tmux copy-mode is the only real history. xterm's own mouse-mode state can be stale after a reload.
- One-finger vertical drag reaches nothing (F1). Scrollbar = local buffer only (F5). Focus is pulled back 3-9 ms after keyboard dismiss (F2, `handleViewportResize` → `focusTerminal`). Every viewport change snaps to bottom on touch (F3, `scrollToPrompt = keyboardOpen || hasTouch`). Input typed in copy-mode is eaten by copy-mode (F8, H2).
- tmux format output replaces TAB with `_` when LANG is unset (walk F15): NEW parsers must use a printable separator.

## Principle
On touch layouts the SERVER decides how a vertical scroll is routed, from tmux's live pane state. The browser never trusts its own xterm buffer/mouse-mode state for touch scroll. Desktop behaviour stays as it is (all client changes gated on `isTouchLayout()`); server additions are new message types that desktop clients never send.

## Backend (slice M0-BE)
1. `backend/services/tmux-scroll-state.ts` (pure): `TMUX_SCROLL_STATE_FORMAT` using `|` as separator and `parseTmuxScrollState(stdout)` → `{inMode, position, total, rows, altScreen, mouseApp, mouseSgr, appCursor, unseen} | null`. Fields from `pane_in_mode`, `pane_mode` (inMode = pane_mode === "copy-mode"), `scroll_position`, `copy_position_limit` (3.8) falling back to `history_size` (3.4), `pane_height`, `alternate_on`, `mouse_any_flag`, `mouse_sgr_flag`, `keypad_cursor_flag` (DECCKM), `pane_unseen_changes`. Clamp position to 0..total.
2. TerminalBackend interface: `readScrollState(session)`, `scrollToPosition(session, n)` (`copy-mode -e` then `send -X goto-line N`; refuse on alt screen; n<=0 → exit), `exitScroll(session)` (`copy-mode -q`, rc 0 even when not in a mode). tmux backend implements all; brokered backend implements through `control()` or returns null/false, and gains the missing `alternate_on` guard in `scrollHistory`; raw backend returns null/false.
3. `ensureServerOptions`: `set-option -gq copy-mode-line-numbers off` (tmux 3.8 changes goto-line semantics otherwise; `-q` keeps 3.4 quiet).
4. WebSocket (`/ws/terminals/:id`), new client→server types (validate strictly, ignore extra fields):
   - Opt-in for `scroll-position` frames is a FLAG IN THE SOCKET URL: `scroll=1` on `/ws/terminals/:id?...` (stored on `ws.data` next to `protocol` and `clientId`, backend/server.ts ~11347-11398). This is the one opt-in mechanism for new server→client frames; slice S2 later adds `agents=1` the same way (docs/plans/2026-10-22-agent-attention-design.md §1.8). Read-only sockets may opt in.
   - `{type:"touch-scroll", direction:"up"|"down", lines:int 1..100, col?:int>=1, row?:int>=1}`: server reads scroll state (cache ≤ 250 ms per terminal is fine) and routes:
     - `mouseApp` → write `lines` wheel reports (cap 10 per message) to the tmux client PTY input exactly as browser input would arrive: SGR `ESC[<64|65;col;rowM` when `mouseSgr`, else legacy `ESC[M` + chr(32+64|65) + chr(32+col) + chr(32+row) (col,row clamped 1..223). col/row default to the pane centre.
     - `altScreen && !mouseApp` → `lines` arrow keys (`ESC O A/B` when `appCursor`, else `ESC [ A/B`), cap 10 per message ("AlternateScroll", herdr `src/pane.rs` WheelRouting; keep only if a real-tmux test proves `less` scrolls).
     - otherwise → existing copy-mode path (`scrollTmuxSessionHistory`, coalescing, ±100).
     Not allowed for read-only sockets (same as `scrollback` today).
   - `{type:"scroll-to", position:int>=0}` → `scrollToPosition`; 0 → `exitScroll`. Not for read-only. Coalesce: an absolute target replaces queued relative scrolls.
   - `{type:"scroll-latest"}` → `exitScroll`. Not for read-only.
   - **Ordering:** input that arrives while a `scroll-latest`/`scroll-to 0` exit is pending for that terminal is written only after the exit finished (per-terminal promise chain; no reordering of input).
5. Server→client `{type:"scroll-position", seq, inMode, position, total, rows, altScreen, mouseApp}` ONLY to sockets whose URL carried `scroll=1` (old pages print unknown JSON frames as terminal text, web/app.js:603-664). Send: after each drained run of copy-mode scrolls, after scroll-to/scroll-latest, to the one socket just before reconnect `ready`, after a resize while inMode, and on a 300 ms trailing throttle on pane output while the last known state is inMode (catches `-e` auto-exit, `q`, other viewers). `seq` strictly increases per terminal.
6. Unit tests: parser (3.8 line, 3.4 line with empty limit, alt screen, not in mode, malformed → null); WS validation (bad types, ranges, read-only refusal, no frames to sockets without `scroll=1`); routing table (pure function `routeTouchScroll(state, msg)` → `{kind:"wheel"|"arrows"|"history", bytes?}`) including encodings; real private-tmux integration tests (short socket dir under /tmp, stop by PID) for: up 6 → inMode position 6; scroll-to 40; scroll-to 99999 clamps; exitScroll twice; `less` on a long file + arrows changes the screen; a pane that enabled `?1000h?1006h` receives SGR bytes. New test files go into `test:unit` (first list).

## Frontend (slices M0-FE-scroll and M0-FE-focus)
All new behaviour only when `isTouchLayout()` (web/app.js:6546). Never fall back across device classes.

### M0-FE-scroll
1. `web/touch-scroll.js` (pure, UMD like `extra-keys-scroll.js`, with `web/touch-scroll.test.js` in `test:unit`): `createTouchScrollTracker({slopPx:10, axisRatio:1.5})` → per move: `{phase:"pending"|"vertical"|"horizontal"|"cancelled", linesDelta}`; px→lines accumulator from row height (one line per row crossed, remainder kept); momentum: release velocity (px/ms over the last ~100 ms) decays ×0.95 per 16 ms frame, stops below a threshold or on a new touch, max ~2 s; second finger → cancelled. Routing is the server's job (no client routing table).
2. Gesture layer `attachTouchScrollGesture(element, terminalId)` at BOTH terminal creation paths, next to `attachTmuxScrollbackWheel` (web/app.js ~14761 and ~16383), only when `isTouchLayout()` and backend mode is tmux. Listeners on the wrapper in CAPTURE phase: touchstart passive (never preventDefault), touchmove passive:false — after vertical lock `preventDefault()` + `stopPropagation()` (kills native pan, pull-to-refresh and xterm's local touch scroll); horizontal lock does nothing (the existing session swipe on touchend keeps working); touchend starts momentum. Lines are batched per animation frame into `{type:"touch-scroll", direction, lines, col, row}` (finger moving DOWN = older output = direction "up"). col/row = cell under the touch start.
3. A drag never focuses the terminal or opens the keyboard; a tap without movement keeps today's behaviour (focus, keyboard); long press unchanged.
4. Scroll indicator (touch only), new `web/scroll-indicator.js` (pure geometry + drag mapping, with test) and a DOM element per tile: shown while `scroll-position.inMode`, hidden otherwise. Right-edge track; handle with a touch target ≥ 44×44 px. The indicator layer sits ABOVE the tile resize handles (`.tile-resize-*`, styles.css ~1381-1388; on a touch tablet the 4 px `.tile-resize-right` is at the right edge, phone walk F5c) and a drag on it must never resize the tile: give it a higher z-index and stop propagation of its pointer/touch events; e2e checks this at 820×1180; dragging maps to `{type:"scroll-to", position}` throttled to one per 60 ms (latest wins); a "Jump to latest" pill (↓, ≥ 44 px) sends `scroll-latest`. Touch-layout pages add `scroll=1` to the terminal socket URL (ReconnectingWebSocket URL builder); desktop pages never do.
5. Typing while scrolled back (touch only): in `ReconnectingWebSocket.sendInput` (web/app.js ~845, the single input choke point), when a per-socket hook says the pane is in copy-mode, send `{type:"scroll-latest"}` once before the input and mark the local state not-in-mode; the server orders the input after the exit.
6. `web/feature-guide.js`: one plain line each for the scroll handle and "Jump to latest".

### M0-FE-focus (H3 policy, phone-walk F2/F3/F11)
1. BEFORE removing anything: check whether the start-up pass (`setupViewportResizeHandling` → first `handleViewportResize`, web/app.js ~6515) or the `createTerminal` / session-restore paths rely on the viewport pass to focus the first terminal on a phone, and read the mobile block of tests/keyboard-surfaces.spec.ts (~202+) and tests/mobile-regressions.spec.ts. If something relies on it, give it an explicit focus call at its own site. Then `handleViewportResize` (web/app.js ~17294-17380): keep CSS-var/class writes every pass; re-fit key without `appTop`; never call `focusTerminal` from a viewport pass (fit + `syncTerminalSize` instead, as the editable branch does); scroll to prompt only on a keyboard false→true transition; drop `|| platformDetector.hasTouch` at ~17363. Put the transition rule in a pure helper in `web/mobile-layout.js` with a unit test.
2. `ensureTileVisible` (~1506): return early on mobile tile layouts; otherwise `behavior:"auto"`.
3. Extra-keys / quick-reply chip touchend refocus (~2347, ~2525): refocus only if the helper textarea had focus at touchstart (a tap with the keyboard closed must not open it). Keep the `handleKey` scroll-to-prompt (~2482) and the `switchTo` scroll (tests/mobile-regressions.spec.ts:420-490 depends on it).
4. Soft-keyboard typing scrolls to the prompt: `sendCommittedData` (~15040-15065) calls `scrollActiveTerminalToPrompt()` after sending (touch only).
5. compose-sheet.js:354, 366, 425: `focus({preventScroll:true})`; 425 stays synchronous in the gesture.
6. Reconnect/visibility (~15887, ~15985, ~6557): on touch, do not focus unless the helper textarea had focus before; keep the replay-complete scroll.
7. iOS pan mitigation (unverifiable in Chromium; owner checklist covers it): on touch layouts pin `.xterm-helper-textarea` near the top-left of its terminal with CSS (`top:0 !important; left:0 !important`), so the keyboard never has to pan the page to reveal the caret.
8. Dimension overlay (F11): on touch layouts, do not show the "COLSxROWS" badge for resizes caused by the keyboard or the extra-keys row.

## Tests (e2e on 4174 only; red first)
`tests/mobile-touch-scroll.spec.ts` and `tests/mobile-focus.spec.ts`, using `./fixtures` and `test.use({viewport, hasTouch:true, isMobile:true})` (deviceScaleFactor 1: DPR 2-3 has a headless WebGL scaling artifact), at 390×844 and 820×1180 (assert which chrome the context really got). CDP `Input.dispatchTouchEvent` drags. Read visible rows from the xterm buffer (`viewportY .. viewportY+rows`), not `.xterm-rows`.
- scroll: tmux shell with `seq 1 400`: upward finger drag (finger moves down) shows earlier numbers and the indicator; downward drag returns; handle drag moves the view; "Jump to latest" returns to the prompt; a mouse-reporting app (`printf '\e[?1000h\e[?1006h'; cat -v`) receives `^[[<64;` on a drag; `less` scrolls on a drag (AlternateScroll); sideways swipe still switches sessions; a drag does not focus the helper textarea.
- focus: helper textarea focused, viewport height shrunk ~45 % to simulate the keyboard, 40 characters typed with two height changes in between: focus stays on the textarea, `window.scrollY`, `visualViewport.offsetTop` and the container scroll stay unchanged; after a blur + viewport growth (keyboard dismissed) focus does NOT return to the textarea; while in copy-mode, a viewport change does not leave copy-mode; typing in copy-mode reaches the shell.
- Locking: during the build, every Playwright run on 4174 went through one host lock, so only one e2e run used the dev server at a time.

## Decided for the owner (tier 2, reported back)
- A tap on an extra key or quick-reply chip with the keyboard closed does not open it (only refocus when the helper textarea had focus at touchstart).
- Reconnect, tab return and viewport changes keep the reader's position when scrolled back (no snap to bottom unless the keyboard just opened or the user types).
- Typing while scrolled back on a phone first returns to the latest output, then the keys reach the shell (no keys eaten by tmux copy-mode).
- Not in M0, recorded in the review note with a reason: reload opens a different session (F7), all tabs named after the folder (F13), locale-dependent tmux-client-size parser (F15), tablet gets phone chrome (F9, existing design), PgUp/PgDn hidden in row 2 (F6, superseded by touch scrolling), More sheet below the fold (F10), first load skips the launcher (F14).
- The headless WebGL text-size artifact at DPR 2-3 goes on the owner's phone checklist ("is the text normal size, or 2-3x too large?"); if real on a phone it becomes P1.

## Changed by the review fixes
- Wheel reports are always sent in the SGR format; tmux converts them into the pane's own mouse mode. The legacy encoding was not byte-safe above column 95.
- The server also enforces the "leave scrollback before typing" rule for sockets with `scroll=1` (a barrier with a confirmed exit), so it no longer depends on the page's view of the scroll state. Held input is bounded (256 KiB) and so is the per-terminal queue (128 operations); tmux calls have hard timeouts.
- Backends that cannot read the pane state (the per-user broker, raw PTY) do not offer the scroll controls: a touch drag there falls back to the plain history scroll.
